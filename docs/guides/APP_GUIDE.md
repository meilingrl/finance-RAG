# 金融文档证据问答：运行、复核与复现指南

本文对应当前仓库入口 `scripts/course_entry.py`。所有命令从仓库根目录执行；路径中的 `RUN_ID`、`/absolute/...` 是需要替换的占位符。默认使用 Python 3.12。不要把本机作者目录、历史运行 ID 或未随包提供的文件视为新机器已有资源。

## 1. 先确定验证目标

本项目提供源码与结果说明，数据、模型、密钥和原始运行工作区不放在 Git 中。缺少某一资源时，应报告被阻塞的验证层级与具体缺项；不能仅因没有 API 权限判定所有实现都无法运行，也不能以软件测试通过代替真实结果复现。

| 验证目标 | API 密钥 | 本地模型权重 | 数据/运行材料 | 可以得出的结论 |
| --- | --- | --- | --- | --- |
| 标准库合成演示及核心算法测试 | 不需要 | 不需要 | 程序自建合成输入 | 基础处理、规则和算法接口可执行；不是实验成绩 |
| 全量工程测试、网页启动 | 不需要 | 通常由测试替身隔离；可选真实资产测试可能跳过 | 测试夹具、已安装依赖 | 工程行为通过已执行的用例；跳过项单列 |
| 真实资料上的 BM25＋E1 单题 | 不需要 | **不需要** | 完整、已登记的输入问题与证据 | 本地检索和规则抽取可运行 |
| 真实资料上的 MiniLM＋E1 单题 | 不需要 | 需要 MiniLM | 完整输入与模型绑定 | 本地神经检索和规则抽取可运行 |
| 查看报告与已保存聚合结果 | 不需要 | 不需要 | 报告或聚合结果文件 | 能阅读已有结果；不等于重新计算 |
| `verify` 复核已封存正式结果 | 不需要 | 不重新推理；登记清单中的模型文件仍可能被资源检查要求 | 原完整工作区、同 SHA 的资源与隔离金标 | 重新校验封存与计算指标；不是重新生成答案 |
| E2/E3/E4 单题或真实正式重跑 | 需要授权、可用额度 | MiniLM 条件需要 | 合格资源包；正式运行另需冻结配置 | 实际调用与实验复跑；服务变化可能导致输出差异 |

**规则没有单独的“规则权重文件”。** BM25 是本地词项统计检索，E1 是代码中的规则抽取；实现见 `src/ragpilot/` 与 `formal_src/baseline.py`。`model_missing`、`local_model_projection_incomplete` 指向 MiniLM 或正式资源清单，不意味着规则权重遗失。

**执行者无权配置 API 密钥时**：先完成第 2、3 节，再按已有材料执行第 6 节。真实生成明确记为“未执行：缺少授权凭据/调用权限”，向提供者请求授权运行环境或封存结果资源。不要编造密钥、绕过鉴权、静默改用其他模型，也不要把合成回答填写为真实实验结果。

## 2. 无密钥、无模型、无需下载数据的最小验证

机器有 Python 3.12 即可运行以下标准库流程；不需要先安装网页依赖。每次使用新的输出目录，避免覆盖历史结果：

```sh
python3.12 --version
CHECK_ROOT="$(mktemp -d "${TMPDIR:-/tmp}/finance-rag-check.XXXXXX")"
python3.12 src/pilot.py demo --output "$CHECK_ROOT/fixture"
PYTHONPATH=src:scripts:tests:. python3.12 -m unittest \
  tests.formal.test_methods tests.formal.test_run_plan -v
```

预期：命令正常退出；演示生成标注为 `synthetic_software_fixture` 的结果，单元测试结尾为 `OK`。演示验证早期 BM25/规则管线，第二条测试验证现行方法和计划编译；这不是主集 200 题实验。规则弃答属于允许的输出，不能仅凭空答案判定程序崩溃。

若没有 `python3.12`，先检查可用解释器版本；不要直接用不兼容版本的报错判断算法。若环境不允许安装软件，记录环境限制并请求 Python 3.12 环境。

## 3. 应用安装与启动

### 3.1 安装网页依赖

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements/requirements-app.txt
.venv/bin/python scripts/course_entry.py --help
.venv/bin/python scripts/course_entry.py serve --no-browser
```

打开 `http://127.0.0.1:8765`。不带子命令启动会尝试打开系统浏览器；无桌面环境使用 `--no-browser`。可通过 `serve --port 8766 --no-browser` 换端口。服务只绑定本机回环地址；远程容器需由有权限的人设置端口转发，不要把访问不到远端的 `127.0.0.1` 当作应用未启动。

当前代码使用 Unix `fcntl`。macOS 是已有实际验证平台；Linux 需检查 Python/依赖与 CPU 平台，最小容器还需系统命令 `ps`（通常来自 `procps`）。原生 Windows 不受支持，启动入口会明确提示而不是显示导入堆栈。Windows 用户可在 WSL 的 Linux shell 内克隆项目、准备 Python 3.12 和 `ps`，再执行上方 Unix 命令；请在 Linux 文件系统中创建虚拟环境，不复用 Windows/macOS 虚拟环境。本轮未做 WSL 整机验收。

平台锁定依赖位于 `requirements/`，优先按直接依赖清单安装。网络不可用时，请管理员提供与 Python 版本、CPU 架构匹配的离线 wheel 或已配环境；下载失败不是本地算法执行失败。不要混装 macOS、Linux x86_64、Linux aarch64 的锁文件。

### 3.2 工程测试

```sh
PYTHONPATH=src:scripts:tests:. .venv/bin/python -m unittest discover -s tests -t . -v
node --test tests/web/*.cjs
```

Node 仅用于前端测试，不是运行 Python 服务的前提。缺少 Node 时应记录“前端测试未执行”，仍可继续 Python 检查。完整测试含子进程与超时测试，可能需要数分钟；不要因短时间没有输出就认定挂起。记录实际运行项、失败与跳过理由，不能把 skipped 算作通过。合成 provider 用于工程测试，不消耗真实 API 额度，也不证明外部服务可用。

### 3.3 工作区与界面

页面顺序为“配置与资源 → 单题演示 → 正式实验 → 结果复核”。首次克隆仓库时，这些页面不保证已经有资料、权重或旧运行。

默认结果工作区是 `artifacts/formal-v1`，若存在本机 `artifacts/app-entry.json` 则使用其中设置。显式参数优先：

```sh
.venv/bin/python scripts/course_entry.py \
  --workspace /absolute/result-workspace serve --no-browser
```

选择可写的空目录或已有应用工作区，不要指向源码、数据目录或它们的父目录。网页修改保存结果位置需要重启；旧文件不会自动搬迁。刷新网页不重新启动实验，监控断开时先重新加载运行 ID。

## 4. 数据与 MiniLM：准备、登记、校验

### 4.1 自动取得固定课程资源

正常启动会在后台自动取得[固定课程资源](https://github.com/meilingrl/finance-RAG/releases/tag/fixed-data-v1)，依据 `configs/fixed_dataset.json` 验证每个分片、组装后的ZIP和完整文件清单，再原子安装到当前仓库的 `data/fixed-course-v1/`。固定主集为200题、40来源，保留原分组与资源字节；另含12题开发演示与固定MiniLM。下载过程中页面仍可访问，展示进度；中断或校验失败不会覆盖已有数据，可在配置页重试。

主集目录为 `data/fixed-course-v1/formal`，演示目录为 `data/fixed-course-v1/demo`，启动后自动登记。路径按每台机器的仓库位置计算；旧工作区里的作者绝对路径无需拷贝。页面默认主集，不再将 `data/formal-v1` 的未就绪全量候选当作正式资料。

可以单独安装或核验（不调用生成API）：

```sh
.venv/bin/python scripts/setup_data.py
.venv/bin/python scripts/setup_data.py --check
```

离线机器可转移完整已安装的 `data/fixed-course-v1/`，或由提供者交付同SHA的组装ZIP后执行 `scripts/setup_data.py --archive /absolute/fixed-course-data-v1.zip`。已有目录冲突时会保留并报告；不会通过覆盖文件或改写SHA假装通过。资源格式和归属见[固定包说明](../delivery/fixed-dataset/BUNDLE_FORMAT.md)。高级手工登记仍可用于其他资料。

### 4.2 从固定公开来源准备新候选包

以下步骤会访问公共数据/模型下载站点，需要网络，但不调用生成模型 API。使用未被审核或冻结的新目录；不要覆盖现存实验资源。

```sh
.venv/bin/python scripts/prepare_formal.py --output data/formal-v1
.venv/bin/python scripts/prepare_formal.py --output data/formal-v1 --build-inputs
.venv/bin/python scripts/provision_formal_encoder.py --output data/formal-v1
```

第一步按 `configs/formal/source_protocol.json` 获取和划分原始资料，第二步从输入构建问题盲证据、裁图和结构草稿，第三步下载并登记模型。每一步完成后先检查输出：采集脚本可能将异常写入 JSON 的 `blocking_error` / `detail_code`，而仍以退出码 0 结束；出现这些字段或预期文件缺失时先处理，不继续执行下一步。保留 TAT-DQA 的 CC BY 4.0 归属。数据需要问题、PDF/OCR、输入证据与隔离评价资料，只有问题文本或只有论文中的结果表不能替代完整资源包。

**这些命令只产生候选材料，不自动重建历史已合格的 `main_only` 资源包。** `prepare_formal.py` 会留下资格待办，成功退出不代表可以冻结正式运行。新候选包与固定课程主集是不同入口；不要用未完成准备的全量候选替换已校验主集。精确复核历史报告，优先要求提供者交付原同 SHA 资源及资格证据；独立重建则按检查结果补齐并记录新的资源身份，不手工把资格字段全改为 `true`。

模型为 `sentence-transformers/all-MiniLM-L6-v2`，固定 revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`。文件名、大小、SHA 与下载地址在 `configs/formal/minilm-files.json`。第三步要求第二步之后的资源清单存在；只下载权重到任意缓存目录不等于已经登记到应用。

### 4.3 编码器运行依赖

```sh
.venv/bin/python -m pip install -r requirements/requirements-encoder-runtime.txt
```

模型文件准备好，还需 `sentence-transformers` / `torch` 等运行依赖。项目加载 MiniLM 使用 CPU、`local_files_only=True`、`trust_remote_code=False`，运行检索时不会自动替你下载缺失权重。不要求 GPU；不要将“没有 CUDA”当作阻塞条件。

离线机器可以由有权限者预先下载固定版本文件，按清单校验后转移完整资源包。模型下载留下 `.part`、文件大小或 SHA 不符时，先保留失败文件与错误记录；在新候选目录重新准备，或由维护者确认后移走单个不完整文件再重试。不要关闭 SHA 检查，也不要直接更改清单以接受其他模型。

### 4.4 自动课程检查与人工审核模式

| 模式 | 含义 | 是否必须有人签署语义审核 |
| --- | --- | --- |
| `automatic_course` | 课程范围：自动校验资源并对官方金标评分，结果标注未人工审核 | 不要求；但不取消文件、分组、来源、兼容、吞吐和预算证据检查 |
| `human_reviewed` | 保留的人工审核协议 | 需要符合要求且绑定精确 SHA 的审核材料 |

网页“使用正式资料候选包”明确按 `automatic_course` 登记默认目录。输入其他自定义正式资源路径时，不能假设自动采用课程模式；默认路径以外的登记需由维护者通过现有资源登记接口明确传入 `review_policy: "automatic_course"`，或使用已经正确登记的课程资源。

出现 `reviews_missing` 先确认实际模式与资源 ID；不要将旧人工模式的阻塞误认为课程自动模式也必须人工签署。反过来，自动模式中的 `qualification_*`、图像/结构缺失、SHA 不符仍必须处理。E3 需要真实裁图及绑定，E4 需要与证据身份对应的结构；没有这些材料时先验证 BM25＋E1，不能伪造审核记录或用空图片替代。

## 5. 有授权时执行真实生成

### 5.1 模型与密钥

完整课程运行依赖请安装 `requirements/requirements-course.txt`。在页面填写模型服务基础地址或完整 Responses / Chat Completions 地址、模型名称及会话密钥；协议可自动识别，高级区可调整输出上限、推理强度、流式响应和JSON格式。密钥只留在服务内存，重启服务后需重新输入；浏览器或旧工作区不包含可复用的密钥。不要将密钥写入报告、请求 JSON、截图或 Git。

配置区“检查模型能力与并发”和正式页“准备并检查”会实际验证文本、图像及所选 N 路并发；图像标记只存在于合成图片中，文本成功不会被当成图像支持。N=1时无需另发并发请求。若完整计划使用对照模型，还会检查该模型所需能力；主集不会因填写了不用的对照模型而多发请求。页面显示实际调用次数，全部记入账本。JSON格式协商出的实际参数会保存并冻结，不能以未生效配置获得通过。

正式模型采用已保存值，不限定厂商。支持Responses与Chat、流式/非流式及有效生成参数。主集只要求主模型；完整计划包含第二模型的图像条件，所选对照模型须真正支持该输入。正式并发可填写1–32，默认4，单题始终串行。更换配置、凭据或服务重启后，由程序重新完成所需检查；历史成绩继续属于原快照，不能改写成新模型结果。

模型检查和正式准备在当前服务会话中后台执行。页面刷新后读取原检查状态，不自动重新提交；连接中断可点击配置区“继续查看原检查”。检查完成后如果配置写回失败，该入口仍保留，重试只应用原结果。浏览器无法保存恢复记录时会明确提示保持本页打开；此时内存后备仅在本页有效。服务重启会失去检查句柄与会话密钥，不会自动重发未知请求。原有同步 API 与 CLI 保持可用。

### 5.2 单题与正式实验

1. 启动后等待固定资料自动准备；BM25＋E1单题无需密钥。
2. 填写模型与有效密钥。正式页点击“准备并检查”；程序自动选择固定主集，核验分组、来源、证据与评价ID，测试服务能力，再冻结当前代码、资料和配置。
3. 显示“准备完成，可启动”后点击启动；运行记录与实际请求次数持续落盘。旧模型配置、旧代码身份与旧累计次数不会作为新实验的前置条件。
4. 修改配置后再次准备即可生成新快照；活动任务期间不能替换配置。旧快照位于工作区 `profiles/history/`，旧结果和账本保留。恢复旧任务仍使用其原冻结版本，不能把新配置注入旧任务。

课程模式按本次run记账，每个逻辑生成最多尝试3次（首次加最多2次可恢复重试）；主集3600个生成对应最多10800次尝试。历史调用累计保留，不清空账本，也不再用另一场实验的8000次总额度阻止新实验。人工研究模式仍保留其原始预算协议。

**报告实际主集与完整计划不同。** 已完成报告是 `main_only`：200 题、40 来源、3,600 个逻辑生成单元及 800 个本地基线单元。完整计划还包含诊断、消融和第二模型，合计 6,600 个逻辑生成单元及 1,000 个本地基线单元；不能把这些计划项目称为已完成。实际调用次数还受同轮复用和重试影响。范围由绑定资源/计划决定，不是把 UI 名称改成“主集”即可。

正式范围必须包含两种检索器，因此正式预检可能要求 MiniLM，即使当前只想检查规则。只验证无权重路径应选择开发单题或合成测试，而非绕过完整正式预检。

开始后保持冻结代码、配置与资源不变。目录迁移也可能改变代码身份；旧任务出现 `code_changed` 时，应在与该任务对应的代码版本恢复，或新建工作区按当前版本重新冻结新实验。不要改旧 `spec.json`、删账本或修改 SHA 强行恢复。

### 5.3 CLI 执行

```sh
.venv/bin/python scripts/course_entry.py \
  --workspace /absolute/result-workspace execute --request request.json
```

`request.json` 必须引用本工作区已登记的 `profile_id` 和 `resource_set_id`，合同见 `formal_src/contracts.py`；最常规的使用方式是在页面创建任务。执行生成任务时，由有权限者通过进程环境设置 `FORMAL_API_KEY`，不要放入请求 JSON 或命令行实参。无 API 的 E1 请求不需要密钥；正式实验包含生成任务，不能省略密钥。

## 6. 无 API 复核已有实验结果

仅得到 Git 仓库或课程 ZIP 中的聚合表，不能重新计算逐题指标。请提供者交付以下材料；缺项需在复核记录中列出。

- 完整原应用工作区，包括 `runs/RUN_ID/`、对应方案与资源登记记录；运行中包括原 `spec.json`、`tasks.json`、`inputs.json`、`predictions.jsonl`、`sealed.json` 和已有结果证明等文件。不要只复制预测或汇总表。
- 同 SHA 的资源包及隔离评价文件，保留 `resources.json` 和相对路径。人工模式还需相关审核材料，课程自动模式如实标注没有人工审核。
- 可访问、可读的资源位置和匹配运行的源码/协议说明。哈希清单只证明身份，不代替数据文件或可访问的交付位置。

将工作区复制到可写新位置，在该工作区启动服务并登记同内容资源的新位置，然后加载原运行。不要编辑封存文件中的旧路径字符串；它们参与历史身份核对。旧运行对应的资源 ID、清单与绑定需要保持一致，注册一个无关的新 ID 不会修复原运行的评价依赖。

```sh
.venv/bin/python scripts/course_entry.py \
  --workspace /absolute/result-workspace verify --source-run RUN_ID
```

CLI 输出任务状态 JSON；最终 `state=completed` 且退出码 0 表示该复核任务完成，非完成状态返回 2。`verify` 不发送生成请求、不需要 `FORMAL_API_KEY`，会创建独立复核输出，原封存预测不重写。正式结果应查看 `engineering.verification_kind=sealed_evaluation`、`evaluation_status=scored` 及指标；单题演示的 `integrity_only` 只表示完整性检查，不代表测试集评分。

本地复核不会重新编码，但应用资源检查仍核对已登记清单。如果清单包含模型文件而交付时漏掉，仍可能报资源缺失；应补齐同版本文件，不能删掉清单条目绕过身份检查。账本损坏或分类额度状态也可能阻塞当前应用预检，先检查返回的具体原因；无 API 并不代表无需任何配套材料。

## 7. 异常处理与合理判定

按“保留原错误 → 确认目标层级 → 检查前提 → 修复/补齐 → 新任务验证”的顺序处理。记录错误码、Python/系统版本、命令、资源检查结果和运行 ID；不要收集密钥或完整私有请求正文。

| 现象或错误 | 常见原因 | 处理方式与结论边界 |
| --- | --- | --- |
| `ModuleNotFoundError: fastapi` / `uvicorn` / `fitz` | 使用了未装依赖的解释器 | 用 `.venv/bin/python -m pip ...` 安装并用同一解释器启动；记录依赖前提未满足 |
| `fcntl` 不可用 / `ps` 不存在 | 平台或系统工具不满足 | 采用已支持的 Unix 环境、由管理员补齐系统工具；不要声称原生 Windows 已验证 |
| pip 下载超时、无可用 wheel、TLS 失败 | 网络、镜像、证书或平台版本问题 | 检查网络与架构，提供匹配的离线包/环境；不要随意取消版本固定或 TLS 校验 |
| 资料状态连接暂时中断 | 状态请求失败，下载可能仍在后台继续 | 页面自动退避重连，也可点击“刷新资料状态”；不会重复提交实验 |
| `fixed_data_conflict` / `fixed_data_permission_denied` | 已有资料校验失败或目录不可写 | 保留原资料；按提示核对固定版本或修复目录权限，不通过反复下载覆盖冲突目录 |
| 端口占用、浏览器打不开 | 端口冲突、无 GUI、远程回环地址 | 换端口、用 `--no-browser`，核对服务所在机器和端口转发 |
| `credential_required`、HTTP 401/403 | 无密钥、密钥失效、模型/项目无权限 | 由授权者配置；无权限时继续无密钥路径，并标明真实生成未执行 |
| `model_not_in_catalog`、协议/响应格式错误 | 服务模型名或 Responses 能力不匹配 | 核对实际服务能力；不要用任意模型替换正式协议并宣称复现 |
| `resources_missing`、`Resource directory missing`、`resources.json required` | 只有源码、路径错误或资源包不完整 | 获取完整资源包并按实际目录登记；不以空目录替代 |
| `model_missing`、`local_model_projection_incomplete`、编码器加载失败 | MiniLM 未下载、未登记或运行依赖缺失 | 按第 4 节补模型/依赖/绑定；先用 BM25＋E1 验证无权重实现 |
| `resource_missing`、`resource_sha_mismatch` | 文件缺失、损坏或使用了另一版本 | 从原来源恢复匹配字节；新数据应建立新身份，不修改旧 SHA |
| `reviews_missing`、`preregistered_audit_plan_required` | 正在使用人工协议或旧资源登记 | 确认模式；课程资源应明确按自动模式登记，人工协议应提供真实审核记录 |
| `qualification_*`、`qualification_evidence_missing` | 候选资料尚未完成对应资格检查 | 取得匹配资格证据或按实际流程补齐；自动模式也不能跳过完整性/来源/兼容检查 |
| E3 图像绑定缺失 / E4 结构身份变化 | 裁图、结构和证据不一致 | 在未冻结候选包中重新准备并校验，保留原资源；不要伪造空文件 |
| `profile_not_frozen`、`model_profile_required` | 未采用模型方案或尚未冻结 | 先完成资源与模型前提，再冻结、预检；冻结失败要读具体原因 |
| `code_changed`、`resources_changed`、`profile_changed` | 与封存/冻结身份不一致 | 恢复原版本或以新工作区开展新实验；不要篡改旧记录 |
| `source_not_sealed`、`evaluation_gold_missing` | 原运行未完整结束或评价包未交付 | 补齐原封存材料/评价资源；暂不能独立复核，不等同于源码测试失败 |
| `budget_exhausted`、`category_budget_exceeded` | 实际尝试达到协议限制 | 停止并审查授权与实验计划，不删除账本获得“新额度” |
| 429、408、5xx、连接断开或流未结束 | 服务限流、网络或上游异常 | 按第 8 节等待有限重试、查看落盘状态；网络恢复后按原运行恢复 |
| `execution_slot_busy` | 已有任务占用执行槽 | 查看当前任务，不重复创建正式运行 |
| E1 `abstained` / 答案为空 | 规则无法唯一可靠抽取 | 是方法允许的弃答；记录为覆盖/准确性结果，与程序异常区分 |
| 只看到论文表格，找不到原预测 | 交付仅包含聚合结果 | 可以阅读结果，不能宣称逐题复核完成；请求原运行与评价资源 |

如果在满足前提后仍发生同一异常，应保留最小复现和日志，按实际证据报告程序缺陷；本指南不要求审阅者忽略真实失败。

## 8. 网络异常、中断与恢复

课程自动模式对可重试错误最多尝试 3 次，中间等待 2 秒、4 秒。覆盖超时/连接错误、HTTP 408/429/500/502/503/504 及部分不完整流/解析错误；最终失败会按协议落盘并进入统计。鉴权和配置错误应先修复，不能通过持续重试解决。每次尝试都计入预算。

最近 100 次中技术失败超过 5 次会触发暂停；界面 150 秒无新进展提示是排查信号，不等于断定进程死亡。先查看运行状态、已保存数量与 `request-errors.jsonl`，其中记录错误类别、时间、尝试及可得的 HTTP/流诊断，不记录密钥和完整正文。

网络恢复后，在原运行监控中恢复。已保存回答不会重跑；健康窗口在新的课程工作进程中重新统计，历史失败和额度仍保留。服务重启后重新填写会话密钥。暂停/取消需等待在途结果落盘。

若进程退出留下发送结果未知的请求，先核对供应商记录和本地已保存响应。界面可要求填写核对依据，明确将无法确认的请求记为失败后再恢复；这样会影响指标，不能假定等同于未发送或免费。不得删除账本、改预测或反复新开任务来跳过未知状态。

## 9. 课程交付与复现说明

课程导出要求真实报告、摘要、成员信息、贡献声明、AI 使用声明，以及满足当前协议的封存评分结果。课程自动模式接受如实标注未人工审核的结果；人工协议另检查审核材料。旧错误码 `formal_results_not_complete_and_reviewed` 是通用阻塞名称，不能单凭名称断定自动模式强制要求人工审核。

课程包不超过 50 MB，包含白名单源码、配置、必要测试、聚合结果及运行身份；不包含数据、权重、环境、密钥、完整原始请求或 Git 历史。它不是无需外部材料即可重跑全部实验的自包含包。提供者应另给资源获取方式、SHA、可访问性说明及必要的原运行工作区；没有实际可获取的资源时，应明确说明独立复现尚受交付缺项限制。

建议审阅记录分别写明：已执行的软件测试、实际平台、是否启动成功、可用资料/权重、是否有真实 API 授权、是否完成封存结果复核、真实生成是否执行及未执行原因。报告实际完成范围与代码中的完整计划分别判断。

当前源码入口关系：`app/` 与 `web/` 提供交互，`formal_src/` 实现正式协议与评价，`src/ragpilot/` 提供基础检索/规则能力，`scripts/` 提供命令入口，`configs/formal/` 固定协议与模型清单。主集结果见仓库的 `docs/experiments/MAIN_RESULTS.md`；课程导出包的结果以 `results/` 和 `runtime/configuration.json` 为准。


## 运行诊断与页面回归

启动失败、工作进程内部错误、后台检查异常会尝试保存一份最新的 `diagnostics.json`：运行错误位于对应 `runs/<run_id>/`，服务/检查错误位于当前结果工作区。记录只含诊断编号、时间、异常类型及代码文件名/函数/行号，不记录异常原文、局部变量、请求正文或模型回答；文件权限为仅当前用户可读写，采用原子替换且内容有界。故障运行的恢复面板可查看记录。诊断文件不参与实验封存、评分或课程导出；无法写入诊断也不改变原错误处理。

事件 API 保留原数组格式及 `after_seq` 参数。页面增量读取，明细展示最近100条；完整事件仍保存在原运行目录的 `events.jsonl`，运行计数不变。

已有 `node --test tests/web/*.cjs` 可运行无浏览器测试；真实页面测试在找不到 Playwright 时明确跳过。可在独立测试环境安装 Playwright 及对应 Chromium，再运行同一命令；使用已安装 Chrome 时设置 `RAG_BROWSER_CHANNEL=chrome`。浏览器测试启动临时本地服务并模拟 API，不连接用户运行实例或真实模型服务。

源码身份属于正式冻结内容。升级时保留旧 checkout 与旧结果工作区，旧任务继续在原版本恢复；新版本使用独立工作区，按原流程准备、冻结后启动新实验。不修改旧快照的代码哈希来绕过校验。
